# PathSnap — Map-Matching & Route Reconstruction

Noisy GPS trajectories → road-arc sequence. A learned candidate scorer (six
models compared, LightGBM selected and Bayesian-tuned) feeds an HMM/Viterbi
decoder over the directed road graph. A FastAPI backend (laptop 1) serves
predictions and computes accuracy against its private reference routes; a
static evaluator UI (laptop 2) lists the evaluation trips, sends the selected
trip ID and shows the predicted route and scores.

Headline numbers (all from files in `results/`, reproduced by the commands
below) are in the technical report `report/PathSnap_Technical_Report.pdf`.

## Installation

```bash
python3.12 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

The raw data is **not** committed. Point `PATHSNAP_DATA` at the folder that
contains the partition sub-folders (`train/`, `student_test/`, …), each trip
being a folder `<trip_id>/` with `<trip_id>.track/.nodes/.arcs/.route`. By
default the code looks for `../Student folder` next to this repository.

```bash
export PATHSNAP_DATA="/path/to/Student folder"
```

## Reproducing every result

```bash
python scripts/eda.py               # dataset inventory -> results/eda_trips.csv
python scripts/build_dataset.py     # candidates + features + labels (cache/)
python scripts/eda_plots.py         # EDA figures + data-quality table
python scripts/baseline.py          # nearest-segment geometric baseline
for m in logreg gnb knn rf lgbm mlp; do python scripts/train_models.py $m; done
python scripts/bayes_opt.py 40 2700 # Optuna TPE on LightGBM (trial log in results/)
python scripts/train_models.py lgbm_tuned
python scripts/hmm_eval.py lgbm_tuned   # decoder grid on train OOF + test ablation
python scripts/model_plots.py       # comparison figures + tables
python scripts/make_maps.py --eda train 00000002
python scripts/make_maps.py student_test 00000009 00000077
python scripts/smoke_test.py        # fresh-process end-to-end check
```

Seeds are fixed (42); folds are stored in `results/folds.json`.

## Deployment (two laptops on the same LAN)

**Laptop 1 – API (model, HMM, road network, private evaluation)**

```bash
export PATHSNAP_DATA="/path/to/data_root"      # contains the evaluation partition folder
export PATHSNAP_PARTITION=evaluator_test        # folder name holding the ten reserved trips
uvicorn api.server:app --host 0.0.0.0 --port 8000
```

Find its LAN IP (`ipconfig getifaddr en0` on macOS, `ipconfig` on Windows) and
allow inbound TCP 8000 in the firewall. Every request is logged to the console
and to `logs/api_requests.log` (method, path, client IP, status, latency, trip,
accuracy).

**Laptop 2 – evaluator UI**

```bash
cd ui
python -m http.server 8080
# open http://localhost:8080/?api=http://<LAPTOP1_IP>:8000
```

The UI lists the trips returned by `GET /trips` (read from the partition
folder, nothing hardcoded), sends `POST /predict {"trip_id": ...}`, draws the
returned GPS fixes and predicted route on a map, and shows the server-side
scores (classifier-only vs classifier+HMM). The map tiles need internet access.

### LAN troubleshooting (checked on our laptop 1)

* `curl http://127.0.0.1:8000/health` works but `curl http://<LAN_IP>:8000/health` from laptop 2 times out →
  the OS firewall is blocking Python. macOS: System Settings → Network → Firewall → Options → allow incoming
  connections for the Python used by `.venv` (or accept the "allow incoming connections" prompt when uvicorn
  starts). Windows: allow Python on *Private* networks in Windows Defender Firewall.
* Both laptops must be on the same network; some phone hotspots and campus Wi-Fi block client-to-client traffic
  (AP isolation). A phone hotspot that both laptops join, or a direct cable, usually works.
* Test from laptop 2 first with `curl http://<LAN_IP>:8000/trips` before opening the UI.

### API

| Method | Path | Body | Returns |
|---|---|---|---|
| GET | `/health` | – | status, model name, partition |
| GET | `/trips` | – | trip IDs available for evaluation |
| POST | `/predict` | `{"trip_id": "00000009"}` | predicted route (arc IDs + line geometry), GPS fixes for display, timings, evaluation scores |

### Leakage guarantees

* Prediction (`pathsnap/pipeline.py`) loads trips with `with_route=False`; it never imports `labels.py`.
* Evaluation (`api/evaluation.py`) runs **after** prediction and returns only aggregate scores — no reference geometry or labels reach the UI.
* Student-test routes are used only by evaluation code; evaluator trips were never available during development.

## Metric definitions (short)

* **Observation top-1 accuracy** – share of GPS fixes whose predicted arc equals the reference arc obtained by monotone alignment of the fix sequence to the `.route` sequence; fixes > 60 m from the aligned route are excluded (reference does not cover them).
* **Macro-F1** – per trip, F1 averaged over the arcs occurring in that trip, then averaged over trips (arc IDs are trip-specific).
* **Candidate miss rate** – share of scored fixes whose reference arc is not in the candidate set.
* **Route continuity** – share of consecutive fix pairs whose predicted arcs are identical or connected head→tail.
* **Route precision / recall / F1** – length-weighted overlap between predicted and reference arc sets.
